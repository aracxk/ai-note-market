# プロダクトビジョンと差別化戦略 (Product Vision & Differentiation)

- **カテゴリ**: メタ・プロダクト定義 (`docs/00-meta/`)
- **サービス名**: AI-Note Market (AI × note アイディア・アセット販売所)
- **コンセプト**: **「読むnote」から「動かして使うAIアセット販売所」へ**

---

## 1. サービスの存在意義とコアミッション

従来の note や Zenn、Brain などのコンテンツ販売プラットフォームは、人間が「文章を読む」ことを前提としたメディアです。
しかし、AI時代に流通するノウハウの多くは、プロンプト、設定ファイル（`.cursorrules`, MCP設定）、拡張機能（Claude Skills, Custom GPTs）、自動化スクリプトなどの **「AIを動かすための実行可能アセット（武器）」** です。

AI-Note Market は、単なるテキスト販売にとどまらず、**「検証済みで即座に動かせるAIノウハウの安全・高速な流通」** を実現する次世代のプラットフォームを目指します。

## 3. 各イノベーションの詳細とアーキテクチャへの反映

### ① 動作検証済みバッジ (Verified Asset)
- **課題**: 「有料プロンプトを買ったのに、AIのモデルバージョンが変わって動かない」「コードがエラーになる」という購入者の不満。
- **解決策**:
  - 記事データ（`Note` 集約）に「対象AI基盤・モデルバージョン・動作確認環境」のメタデータを保持。
  - バッジにより購入者が安心して購入できる信頼性を担保。
- **実装フェーズ**: Phase 1（ドメインモデル定義） ➔ Phase 5（UIバッジ表示）

### ② 1クリック・インポート (1-Click Install)
- **課題**: 購入後、長文のコードや設定ファイルを手動でコピー＆ペーストする作業の煩わしさ。
- **解決策**:
  - `cursor://` ディープリンクを活用し、購入完了画面のボタンからエディタへ設定を直接注入。
  - CLI（`npx ai-note install <note-id>`）によるプロジェクトへの一発ダウンロード。
- **実装フェーズ**: Phase 5（UI連携） ➔ Phase 7（CLIツール連携）

### ③ バージョニングと更新差分追跡 (Versioned Asset)
- **課題**: AIツールのアップデートによってプロンプトの修正が必要になった際、過去の購入者が修正箇所を把握できない。
- **解決策**:
  - 記事集約にバージョン管理（`version: number`）を導入。
  - Gitのコミットログのように、バージョンごとの修正点（Diff）を明確に可視化。
- **実装フェーズ**: Phase 1（集約設計） ➔ Phase 2（更新ユースケース）

### ④ 体験型 Paywall (Interactive Playground)
- **課題**: 購入前に本当に期待通りのクオリティで出力されるのか分からない不安。
- **解決策**:
  - 無料エリアにお試し入力フォームを配置し、有料プロンプトの推論結果サンプルを1度だけ試せる仕組み。
- **実装フェーズ**: Phase 5（Next.js Server Actions & API連携）

## 4. AIによるSEO・メタデータ自動最適化

- **著者の負担軽減**:
  - 著者はノウハウ（本文）の執筆にのみ集中する。
  - 記事の無料エリアおよび本文から、AIが検索エンジン向けタイトル、メタディスクリプション、検索タグを自動生成・最適化する。
- **技術基盤**: Next.js 14 App Router による完全な SSR（サーバーサイドレンダリング）と構造化データ（JSON-LD）の自動出力。

# AI駆動開発とコンテキスト管理指針 (AI-Driven Guidelines)

- **カテゴリ**: メタ・開発方針 (`docs/00-meta/`)
- **テーマ**: セッション初期化・複数AI環境における設計一貫性の担保とコンテキスト管理

---

## 1. 背景と課題

AIを活用したソフトウェア開発では、以下の問題が発生しやすい。

1. **セッション肥大化とコンテキスト消失**:
   - チャットセッションが長期化するとトークン上限に達し、過去に決めた設計判断やルールをAIが忘れてしまう。
   - 新しいセッションを立ち上げた際、過去の文脈を引き継げず、AIが勝手な自己流コード（プリミティブ型の直接使用、独自のエラー処理など）を書き始めてしまう。
2. **マルチAI・チーム開発での不整合**:
   - 開発者ごとに異なるAIツール（Antigravity, Claude Code, Cursor, Copilot 等）を使用した場合、ツールごとに異なる実装スタイルが混在してしまう。

---

## 2. 解決策：Single Source of Truth（正本の一元管理）

上記の問題を防ぐため、**「すべての設計思想、命名規則、エラー設計、テスト方針の正本（原本）を `docs/` 配下に集約する」** という原則を厳守する。

```text
[ 全てのルールの正本: docs/ ]
  ├── 00-meta/conventions.md             # 命名規則・絵文字不使用などの執筆規約
  ├── 00-meta/roadmap.md                 # 現在地とフェーズごとの達成基準
  ├── 01-architecture/04-error-handling.md  # Result型とDomainErrorの使い分け
  ├── 01-architecture/05-testing-strategy.md # AAAパターンと単体テスト原則
  └── 02-domain-models/overview.md       # ビジネスルールと集約の仕様
```

### AI設定ファイル（agent.md 等）の役割
各AIツールの設定ファイル（`agent.md`, `CLAUDE.md`, `.cursorrules` 等）には、ルールの詳細そのものは書かず、**「作業開始前に `docs/` を確認すること」というポインタ（参照指示）のみ** を記述する。
これにより、ルールの二重管理を防ぎ、`docs/` を1箇所更新するだけで全セッション・全AIに最新の規約が即座に反映される。

---

## 3. 新規セッション開始時のお作法（プロンプト手順）

新しいチャットセッションを開始する際、開発者は以下のシンプルな指示をAIに与えるだけでよい。

```text
【新セッション開始時のプロンプト例】
本プロジェクトは docs/ に設計思想と規約が集約されています。
まず docs/00-meta/roadmap.md と docs/00-meta/conventions.md、
および docs/04-learning-logs/ の最新ログを確認してください。
勝手に進めず、現在のフェーズと次のタスクを確認した上で対話形式で進めてください。
```

AIは `docs/` を読み込むことで、過去のセッションの記憶がなくても、初手から100%プロジェクト規約に沿った振る舞いを再開できる。
